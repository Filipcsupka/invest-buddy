## 3. Rating v3 proposal (`etf-v3`)

Goal: the same shape as the stock score (fixed max, percent of evidenced points, bands at 72/60/48, coverage guard) but tailored to funds. Points total 100; percent = earned / evidenced, and groups that do not apply (income for an accumulating fund) are excluded, not counted as gaps. Every threshold is a draft product rule like the stock thresholds; sources for the underlying criteria are the ones already listed in `docs/etf-score.md` (justETF, Morningstar, State Street, WisdomTree, ESMA, Faber). No source sets the exact points.

Coverage is of the denominators stated: IS = in-scope listings (7,590; not ETC/ETN/leveraged/overlay), ST = listings with a stats row (3,037), TR = tracked symbols with bars (340). "After plan" assumes tasks W1-W3 below (stats and bars for every in-scope enriched ETF).

## 6. Risks

1. **Licence.** Vendor terms bar display to others; the owner's informational-output decision rests on the unsigned TASK-064. "Show as much data as possible" widens exposure (holdings, returns, vol). Keep every vendor figure behind `canUseVendorData` and `MARKETS_VIEWS`; the code today lets Plus and trial see the vendor tabs although the docs say owner-only; the owner should confirm which is intended.
2. **Vendor quality.** NetExpenseRatio mixes units; `TotalAssets` has no currency (three UCITS samples look fund-level in USD, unverified); `Holdings_Count` equals the 10-row list for 1,430 funds; `Valuations_Growth` is null everywhere; Technicals beta is 0 for VWCE; credit quality 0; dividend frequency mixes English and German labels; Vanguard share classes share one fund-level AUM. Each rule needs an explicit gap path.
3. **Rating inflation or false precision.** v2 already gives 805 funds 80% or more on 4 facts. v3 requires wider evidence and a coverage guard; thresholds are drafts, absolute bands treat thematic and single-country funds as concentrated, so a "Focused fund" label is needed. Peer percentile needs `Category`, which is not stored yet (all categories unmeasured).
4. **Cost and rate limits.** About 44k-54k calls for the pending enrich plus bars; account limit 100,000 per day; client counters are estimates. A 402 stops the run. Unmapped EU rows (224) will not resolve.
5. **DB growth and runtime.** Holdings 437k rows for 2,666 funds; at about 7,000 funds about 1.1M rows. Nightly score takes about 100-140 s for 9,466 listings with 5 queries each; v3 adds queries, so batch them.
6. **Constraint migration.** `etf_scores` has `earned <= 35`; v3 needs a migration, and `latestEtfScores` filters on `rules_version`, so the old version stays readable but the pages must switch together.
7. **Research cron.** Unsuspended CronJob with unknown scheduling behaviour; if it starts it spends Codex tokens on 150 funds and writes picks with price null; `partial` verification on most picks is likely.
8. **Wording gate and ADR-001.** Bands must stay neutral; ordering and ranking lists are listed as a lawyer question in `docs/legal-pack.md`; the `Rules met` label must not imply advice.
9. **Stocks stay first.** Waves are independent of the stock pipeline except the shared Orca/EODHD budget; schedule the 44k-call drain outside the stock collection hours (collect 00:00, detect 00:35, eodhd-fundamentals 01:30).

## Appendix: SQL used (all read-only, `BEGIN READ ONLY ... ROLLBACK`)

```sql
-- catalog
select instrument_type, enrichment_status, count(*) from etf_catalog group by 1,2 order by 1,2;
select count(*) total, count(*) filter (where last_seen >= current_date-30) recent, count(*) filter (where shortlist) shortlist,
  count(*) filter (where enrichment_status='ok') ok from etf_catalog;
select enrichment_status, enrich_attempts, count(*) from etf_catalog group by 1,2 order by 1,2;
-- picks and runs
select symbol,name,call,conviction,verification_status,first_seen_at,last_seen_at,listing_key,price,jsonb_array_length(evidence) ev from etf_picks;
select id,as_of,adapter,model,status,picks_count,verified_count from etf_research_runs order by as_of desc;
-- scores 2026-11-13
select case when state<>'rated' then 'not_rated' when earned::numeric/evidenced_max<0.4 then 'a <40' when earned::numeric/evidenced_max<0.6 then 'b 40-59'
  when earned::numeric/evidenced_max<0.8 then 'c 60-79' else 'd >=80' end band, count(*) from etf_scores where as_of='2026-11-13' group by 1 order by 1;
select r, count(*) from etf_scores s, jsonb_array_elements_text(rejections) r where as_of='2026-11-13' group by 1 order by 2 desc;
select evidenced_max, count(*) filter (where state='rated') rated, count(*) from etf_scores where as_of='2026-11-13' group by 1 order by 1;
select r->>'id' rule, count(*) filter (where (r->>'evidenced')::bool) evidenced from etf_scores s, jsonb_array_elements(rule_hits) r where as_of='2026-11-13' group by 1;
-- stored vendor payload coverage
with fs as (select distinct on (listing_key) * from etf_fund_stats order by listing_key, as_of desc)
select k, count(*) present, count(*) filter (where v::text not in ('null','""','{}','[]','0','"0"','0.0')) nonempty from fs, jsonb_each(payload) as e(k,v) group by 1 order by 3 desc;
with fs as (select distinct on (listing_key) * from etf_fund_stats order by listing_key, as_of desc)
select count(*), count(total_assets), count(total_assets_currency), count(yield_pct), count(inception_date), count(ongoing_charge_pct), count(net_expense_ratio_pct),
  count(ret_1y_pct), count(vol_1y_pct), count(sharpe_3y) from fs;
-- bars and tracking
select active, detail_status, count(*) from etf_tracked group by 1,2;
select count(distinct t.vendor_symbol), count(distinct b.vendor_symbol) from etf_tracked t left join asset_bars b on b.vendor_symbol=t.vendor_symbol;
-- jobs
select job, status, started_at, duration_ms/1000, counts from job_runs where job in ('etf-score','eodhd-etf') order by started_at desc limit 5;
```
