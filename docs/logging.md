# Reading application logs

Web request logs and batch job lifecycle logs are JSON lines on standard output and standard error. Read them with `kubectl -n invest logs deployment/invest-buddy-web --since=1h` or `kubectl -n invest logs job/<job-name> --tail=100`. Use the `requestId` from a response's `x-request-id` header to find its ingest log line. Job start and end lines share a `runId`.

Logs stay in the cluster's container logs. There is no application log archive or fixed retention period: kubelet rotation can remove older lines, and deleting a pod removes access through `kubectl logs`. Inspect a failed job before its pod is cleaned up.

## Claude subscription usage

The extract and judge jobs record each Claude call in `ai_budget_calls`, including its start and completion time, model, input and output tokens, and cache read and creation tokens. A cutoff records `status=cutoff`, the usage window when known, and `reset_at` when Claude supplies a parseable time. A cutoff exits with code 5, leaves the current gate pending, and prints one `ANTHROPIC CUTOFF` line with the window, reset time and count of completed tickers. The next scheduled run retries work that was not applied, including work from an older pending gate.

With the owner ingest token, read `GET /api/ingest/ai-budget?report=usage` using `Authorization: Bearer <INGEST_TOKEN>`. The response covers the last 90 days. `rolling5hPeak` is the largest measured token total across calls started within any five-hour interval; `tokensPerDayUtc` and `tokensPerIsoWeekUtc` show daily and weekly totals. `cutoffs` gives each cutoff time, job, model, window and reset time or the clock text Claude supplied, while `callsByJobAndModel` counts calls. Old judge ledger rows have only combined `used_tokens`, so their totals cannot separate cache usage. Old extract rows lack an agent field and are excluded because they may include Codex calls.

When `CLAUDE_CODE_OAUTH_TOKEN` can read Anthropic usage, each model job logs `USAGE five_hour=... seven_day=... at start/end` and stores samples in `ai_quota_samples`. The report's `liveUsage` shows observed window peaks, reset times, and the account-wide percentage-point change during each run. Interactive or concurrent use can contribute to that change. A window can reset during a run, so a negative change does not mean the job returned capacity. The documented long-lived `claude setup-token` may have inference-only access and return 403 from the usage endpoint. With that token, live samples and the soft stop are inactive: the job logs `USAGE unavailable (403)` once and continues, and the report falls back to ledger token estimates. An `ANTHROPIC_API_KEY` disables subscription monitoring for API-billed calls. No OAuth token or usage response body is logged or sent to the ingest API.

The default soft stops are 85% of the five-hour window and 90% of the seven-day window. Set `AI_STOP_AT_FIVE_HOUR_PCT` and `AI_STOP_AT_SEVEN_DAY_PCT` to change them. Between tickers the job checks usage at most once every three minutes. On a threshold hit it logs `STOPPING EARLY`, exits 5, and leaves the gate pending. The monthly token and dollar guard is no longer active.
