# EODHD data access

The client lives in `src/data-providers/eodhd/client.ts`. Set `EODHD_API_KEY` in the job environment. It sends requests to `https://eodhd.com/api` with `api_token` and `fmt=json`; it never logs the token. `fetch` and the retry clock are injectable for local tests. HTTP 429 retries honor `Retry-After`; HTTP 402 raises a clear allowance or plan error. `getCallCosts()` gives an in-process estimate by endpoint, counting each attempted request and excluding documented unbilled 402 rejections. It is not the vendor's account ledger.

| Endpoint | Client method | Calls per request |
| --- | --- | ---: |
| `/exchanges-list` | `exchangesList` | 1 |
| `/exchange-symbol-list/{EXCH}` | `exchangeSymbolList` | 1 |
| `/eod/{SYM}` | `eod` | 1 |
| `/splits/{SYM}` | `splits` | 1 |
| `/eod-bulk-last-day/{EXCH}` | `eodBulkLastDay` | 100, plus 1 per symbol in `symbols` |
| `/v1.1/fundamentals/{SYM}` | `fundamentals` | 10 |
| `/calendar/earnings` | `earningsCalendar` | 1 |
| `/news` | `news` | 5 base calls |
| `/sec-filings/{SYM}/form4` | `form4` | 10 |

The [EODHD call limits](https://eodhd.com/financial-apis/api-limits) distinguish requests from billed calls. Paid plans start at 100,000 calls per day and the standard request ceiling is 1,000 per minute. A rejected 402 request is not billed; failed ticker lookups can be. The account's actual allowance belongs to `/api/user`. **UNVERIFIED:** whether 429 responses consume daily calls; the counter includes them conservatively. The ALL-IN-ONE plan's exact allowance is **UNVERIFIED** and is not hardcoded here. The [bulk API documentation](https://eodhd.com/financial-apis/bulk-api-eod-splits-dividends) says `filter=extended` adds profile and technical fields without an extra charge. Those technical fields can be zero for older dates, while market cap and beta are not point-in-time.

## Symbol master

`npm run symbols:sync` fetches `/exchanges-list`, then active `/exchange-symbol-list` rows for US, XETRA, LSE, PA, AS, SW, PR, WAR, MI, MC, ST, OL, CO, HE, VI, BR and LS. Each returned exchange updates `symbols` in its own transaction. The key is `Code.EXCH`, such as `CDR.WAR`; `exchange` stores the requested EODHD suffix, since the row's `Exchange` can be a specific US venue. A complete nonempty active response updates names and metadata, preserves `first_seen`, sets `last_seen`, restores active rows, and marks absent rows on that exchange as `delisted`. Missing exchange codes are logged and skipped. The job records a `job_runs` entry through `runLoggedJob`.

**UNVERIFIED:** PA, AS, SW, PR, MI, MC, ST, OL, CO, HE, VI, BR and LS have not been confirmed as EODHD exchange codes. The runtime `/exchanges-list` check prevents requests for absent codes; it does not map a market to an alternative code. The [exchange API docs](https://eodhd.com/financial-apis/exchanges-api-list-of-tickers-and-trading-hours) confirm US, LSE, XETRA and WAR and state that `delisted=1` returns a separate historical set. This job requests the active set only, so `delisted` means absent from the latest complete active response. It does not import historical delistings predating the first sync.

## Field coverage and limits

- EOD bars provide date, OHLC, adjusted close and volume. Bulk EOD can include previous close, change, moving averages, 250-day range and average volume. The bulk split and dividend responses have different shapes.
- Fundamentals can include `General`, `Highlights`, `SharesStats`, `outstandingShares`, `Earnings`, `Financials` and `ETF_Data`. `filter` narrows the returned payload but does not lower its 10-call cost. **UNVERIFIED:** `Financials::Income_Statement::quarterly` is inferred from the filter pattern, and ETF expense ratio, total assets and holdings field presence varies by fund or exchange. Callers must check the actual response.
- `/v1.1/bulk-fundamentals/{EXCH}` is outside this client. **UNVERIFIED:** its plan access and call cost, so no budget assumption is made for it.
- The earnings calendar provides actual and estimated EPS and report timing for a date window. News provides article text, symbols, tags and sentiment. **UNVERIFIED:** news documentation also says “+5 per ticker”; the client counter records the documented 5-call base and must not be used as an exact bill when ticker parameters are involved.
- SEC Form 4 is for US issuers. Its filing pages contain non-derivative and derivative transactions plus pagination. `links.next` is a relative path without the token; callers can use its offset in another `form4` request. Other markets may return 404.

## Price bars

`npm run prices:eodhd -- --mode backfill` requests `/eod/{vendor_symbol}` and `/splits/{vendor_symbol}` for each active universe ticker and SPY. Run it before the daily job so MA200 has at least 200 sessions. Daily mode uses per-symbol EOD and splits requests for exchanges with fewer than 100 tracked tickers. At 100 or more, it uses whole-exchange bulk EOD and `type=splits` requests at 100 calls each, without a `symbols` filter. The job reports its estimated calls, failures and tickers with fewer than 200 history bars. `--only MSFT,SPY` limits the selected universe. Both modes support `--dry-run`, which reads data but writes no bars, actions or job runs. With no key or database, `npm run prices:eodhd -- --dry-run --fixture --mode daily` and `--mode backfill` exercise the recorded MSFT examples without network access.

The active `symbols` table supplies `vendor_symbol`, exchange and currency. An explicit `instrument_ids.vendor_symbols.eodhd` mapping wins. Otherwise the current `instrument_ids.exchange` selects the home listing, including NASDAQ and NYSE hints mapped to EODHD's US exchange. With no hint, US takes priority; a single non-US match is also accepted. Unresolved symbols and missing currencies are recorded as per-symbol failures while other symbols continue. EODHD bars go into the existing `daily_bars` table with `source_id=eodhd`, vendor symbol and currency; changed values retain their previous source and currency in `daily_bar_revisions`. The scoring readers continue to read `daily_bars`. The existing price collectors remain available.

The job stores EODHD's as-traded open, high, low and close. It never uses `adjusted_close`, which [EODHD says includes dividends](https://eodhd.com/financial-apis/api-for-historical-data-and-volumes) and would introduce future information into historical screening. EODHD says its reported volume is split adjusted; the job divides older reported volumes by the product of subsequent split ratios to recover as-traded volume. Vendor split ratios are stored in `corporate_actions` as `detected_by=vendor`, with the factor defined as new shares per old share. Raw prices and volumes retain split jumps, which the existing corporate-action detection can identify; consumers that need a continuous series must apply recorded split factors as of their own evaluation date. A history refresh can revise prior bars; the revision log retains the old values. The corporate action revision check compares bars only when the old and current source match, so changing vendor cannot look like a split. The fixture proves the parser and storage path, not live vendor coverage.

Tests use static JSON examples from the EODHD [exchange](https://eodhd.com/financial-apis/exchanges-api-list-of-tickers-and-trading-hours), [EOD](https://eodhd.com/financial-apis/api-for-historical-data-and-volumes), [bulk](https://eodhd.com/financial-apis/bulk-api-eod-splits-dividends), [fundamentals](https://eodhd.com/financial-apis/stock-etfs-fundamental-data-feeds), [earnings](https://eodhd.com/financial-apis/calendar-upcoming-earnings-ipos-and-splits), [news](https://eodhd.com/financial-apis/stock-market-financial-news-api) and [Form 4](https://eodhd.com/financial-apis/insider-transactions-api) docs. They make no network calls. The fundamentals and other non-price methods are available to later collectors.

## ETF catalog enrichment

Set `ETF_ENRICH_SOURCE=eodhd` for `npm run etf:enrich` or use `npm run etf:enrich:eodhd -- --limit 20 --dry-run`. The default remains `codex` until an EODHD key is installed. Dry run reads the pending catalog and prints the number of unique symbols and estimated calls; it makes no EODHD requests or ingest writes. A live EODHD run requires `INGEST_TOKEN` and `EODHD_API_KEY`. The scanner image copies the new module. The CronJob lives in the separate infrastructure repository; its environment must select the source there.

The pending API preserves catalog relevance order and joins active `symbols` by ISIN, preferring XETRA. US listings without an ISIN match use `code.US`. The runner fetches each unique symbol once per run and sends batches through the existing ETF ingest schema and shortlist refresh. The fundamentals endpoint costs 10 calls per unique symbol. A run stops before exceeding 500 calls; set `ETF_EODHD_MAX_CALLS` to another positive multiple of 10 to change that cap. Rows beyond the cap wait for the next run. The default `--limit 20` costs at most 200 calls. **UNVERIFIED:** whether ALL-IN-ONE includes the bulk fundamentals endpoint and its billing; this path does not assume it. It avoids duplicate requests, while bulk fundamentals can replace single-symbol fetches after plan access and response shape are confirmed.

`ETF_Data.Company_Name`, `Index_Name`, `Domicile`, `Holdings_Count`, and `Asset_Allocation` supply fields when present. The [ETF glossary](https://eodhd.com/financial-academy/financial-faq/fundamentals-glossary-etf) defines `NetExpenseRatio` as a fraction (multiplied by 100 for `ter_pct`) and `Ongoing_Charge` as a percent. A lone expense ratio of 1% or more, or a lone ongoing charge below 0.01%, is ambiguous and leaves TER null. When both fields are present, their converted values must agree within 0.01 percentage points. TER also stays null outside 0–10%. This marks the row incomplete if TER is needed for a complete record. `World_Regions` weights do not set the catalog region. `TotalAssets` becomes `aum_usd_m` only for a US listing with USD trading currency; **UNVERIFIED:** the asset currency for non-US and UCITS responses, so their USD AUM stays null. **UNVERIFIED:** UCITS ETF field presence and UCITS status in EODHD. Missing fields, replication, and distribution remain null. A null UCITS value preserves an existing catalog value. No model fills missing data. Rows with no vendor symbol get `eodhd_unmapped`; rows without issuer, asset class, or TER get `eodhd_incomplete`. An ISIN mismatch or a non-ETF vendor type also marks only that row incomplete. Incomplete and unmapped rows consume one attempt and leave the pending queue after three attempts. `enrichment_source=eodhd` marks ingested rows; `ok` rows enter the existing shortlist ranking, which reads `ter_pct` and `aum_usd_m` from `etf_catalog`.
