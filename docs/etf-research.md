# ETF catalog, ratings and research notes

The catalog covers Xetra ETFs, active ETFs, ETCs and ETNs, plus US ETFs in the Nasdaq Trader symbol directories. It does not filter by broker access or UCITS status. UCITS is informational, and an IE/LU ISIN or a fund name is only a hint until an issuer source confirms it.

`npm run etf:catalog-sync` downloads the [Xetra file](https://www.cashmarket.deutsche-boerse.com/cash-en/trading/Tradable-Instruments-Xetra), [Nasdaq-listed file](https://www.nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt), and [other-listed file](https://www.nasdaqtrader.com/dynamic/SymDir/otherlisted.txt). The Xetra page supplies a fresh CSV link if the saved URL changes. The job updates `last_seen` for present listings and keeps missing listings in the database. A listing last seen more than 30 days ago is excluded from enrichment and shortlist selection. `first_seen` stays fixed. Xetra keys use the ISIN supplied by the exchange; US keys use `EXCHANGE:SYMBOL` because the directories have no ISIN. Keys stay stable when later enrichment finds an ISIN, so saved fund URLs keep working.

The catalog sync runs Sunday at 05:10 Europe/Bratislava. Enrichment runs Sunday at 05:40 from EODHD fundamentals only (no model), in sequential batches of 20 and at most 500 EODHD calls per run. It reads only pending rows from `/api/ingest/etf-catalog/pending`, posts checked results to `/api/ingest/etf-catalog`, and skips successful rows on later runs. An incomplete result increments `enrich_attempts`; after three such results the row stops retrying. A failed batch stays pending and the runner continues with the next batch. Use `npm run etf:enrich -- --limit 20 --dry-run` to inspect a bounded run. For the first full run, start the same CronJob manually with `kubectl create job --from=cronjob/invest-buddy-etf-enrich invest-buddy-etf-enrich-initial -n invest` after deployment approval. The first run may cover more than 5,000 US ETFs.

The EODHD mapper takes the asset class from `General.Category` when a whole word matches (allocation, then equity, bond, money market, commodity) and from `Asset_Allocation` otherwise. Region comes from `World_Regions` (`Equity_%`, or `Fund_%` for bond funds) and payout from `Dividend_Paying_Frequency`. `ucits_hint` on the catalog is the Xetra hint (UCITS in the name or an IE/LU ISIN) and is never confirmation; `ucits` stays the confirmed value. `ter_gap='ter_ambiguous'` marks a NetExpenseRatio between 0.01 and 0.025 that fits both units and leaves TER null.

Enrichment skips rows that are already `ok`, so a mapping change reaches them only through the remap job. It reads the latest stored payload and stored dividends, makes no vendor calls, and never replaces a stored class, region or payout with null. Run `npm run etf:catalog-remap` (dry run, prints the first 20 changes and counts), then `npm run etf:catalog-remap -- --apply`, which also rebuilds the shortlist. In the cluster, run `node dist/jobs/etf-catalog-remap.js` from the app image with `DATABASE_URL` after approval.

`etf_fund_stats.payload` has two shapes. Rows written before migration 140 hold the bare `ETF_Data` object without holdings; later rows hold the full response root `{General, Technicals, ETF_Data}` with every holding. SQL readers use `COALESCE(payload->'ETF_Data', payload)`; TypeScript readers use `etfPayloadRoot`. The indexed `etf_holdings` table still keeps at most 2,000 rows per listing.

After each enrichment batch, the server rebuilds a shortlist of up to 150 recent ETF and active ETF listings across the global catalog. It groups funds by `asset_class` and `region`, sorts each group by AUM descending, and uses lower TER when AUM is missing. For share classes tracking the same index within a group, an accumulating class is considered first. It then takes one fund per group in repeated rounds until the list reaches 150. ETCs and ETNs stay in the catalog but do not enter the default shortlist. The stored `shortlist_rank` fixes the order passed to research.

## What customers see

The `/etf` page opens on the v3 rule rating (`docs/etf-score.md`). A strip at the top counts the in-scope ETFs (ETF and active ETF) in each band of the latest score run: Rules met, Mostly met, Partly met and Few met, plus Incomplete data and Not rated. Each band links to the catalog filtered to that band. The strip, the catalog order and filters, and Highest rated all read the same score run: the latest `as_of` of the current rules version. A fund without a rated row in that run counts as Not rated, even if it has an older or previous-version score. Below it, the Highest rated block lists up to five funds per asset class, ordered by band, then percentage, then evidenced points. The band already caps a fund with fewer than 70 evidenced points at Mostly met, so a high percentage on few facts does not lead.

The catalog keeps 50 rows per page and the earlier filters. It adds filters for band, evidence (70 or more evidenced points, or Incomplete data), category, TER range and AUM range, and sorts by rating, TER, AUM and 1-year or 3-year return. Columns show the rating with its band and groups with data, TER, AUM in EUR millions, returns, volatility, yield, holdings, top-10 weight, category, asset class, domicile, distribution, index, issuer, region, UCITS, currency and instrument type.

AUM is shown in EUR only when its currency is known: the stored stats state EUR or USD, or the listing is a USD listing on a US venue, whose catalog figure is in USD. USD converts at the latest stored EURUSD close from the last seven days. Without one, a USD figure shows a gap with the note "No current EUR exchange rate". Any other stored figure shows a gap with the note "Currency not stated". TER comes from the latest stats (ongoing charge, then net expense ratio) and falls back to the catalog value.

Fund statistics (returns, volatility, yield, holdings, top-10 weight, category) and the category filter and return sorts need the ETF market view (`etfOwnerView`: owner, Plus, trial or Passive, with `MARKETS_VIEWS=on`). The rating needs `etfScoreView` (`canOpenFunds`). Without the market view, the page shows the catalog TER and the AUM it can convert.

## Model research notes (owner only)

The model notes (`etf_picks`: call, conviction, verification) are the owner's private workflow. Only the owner sees the research table, its call filter, the pick links, the shortlist and last-run figures and the track record link on `/etf`. The pick card (`/etf/[symbol]`) and the ETF track record (`/etf/track-record`) return 404 for everyone else, the owner's free preview included, before any pick is read. The sidebar shows the track record link to the owner only. For anyone else the page drops the `call` parameter before any read, so it cannot filter or reveal a classification.

The research runner is optional. By default it reads the highest rated recent ETFs from `/api/ingest/etf-catalog/top-rated?limit=25`, in the same order as the Highest rated block, with `ratingPercent`, `ratingBand` and `evidencedPoints` as context. `--selection shortlist` (or `RESEARCH_ETF_SELECTION=shortlist`) reads the older catalog shortlist instead, and `--limit` (or `RESEARCH_ETF_LIMIT`, 1 to 150) caps the candidates. The runner sends each batch of 25 to the existing Codex adapter without web search. The model writes a BUY_ZONE, WATCH or AVOID screening note for each listing. The runner rejects a changed catalog identity or cost field, an added listing, a fabricated price, evidence link or figure in the prose. The candidates have no dated price, so price fields stay null. Empty evidence leaves a pick unverified, and the card must not imply that a source page was checked. Each successful batch posts separately to `/api/ingest/etf` and keeps earlier picks and entry prices.

The repo copy of the `invest-buddy-etf-research` CronJob is suspended (`suspend: true`, Monday 07:40 schedule kept). To run it once, after owner approval: `kubectl create job --from=cronjob/invest-buddy-etf-research invest-buddy-etf-research-manual -n invest`. The live object follows only after the infra repo copy changes.

## Measuring picks

The daily ETF outcomes job measures a pick after its stored BUY_ZONE entry reaches 30, 60, 90 or 180 calendar days. It uses the first stored close within seven days of the entry and each due date. For tracked funds, it reads the EODHD vendor symbol linked through `etf_tracked` and its closes in `asset_bars`. The tracked quote currency must match the catalog currency, or the pick currency when the catalog has none. Older US picks can still use `daily_bars` or `discovery_price_bars`. A missing fund series leaves that pick pending.

For equity ETFs, the comparison uses stored closes in the catalog listing's quote currency. US dollar listings on US exchanges retain their saved benchmark, normally SPY from `daily_bars`; if SPY has no entry bar, the job uses GSPC.INDX from `asset_bars`. Other US dollar listings use GSPC.INDX. Euro listings use STOXX50E.INDX, except funds marked Germany, France, Netherlands or Spain, which use GDAXI.INDX, FCHI.INDX, AEX.INDX or IBEX.INDX. The other currency proxies are CHF to SSMI, JPY to N225, HKD to HSI, CNY to SSEC, INR to NSEI, KRW to KS11, AUD to AXJO, CAD to GSPTSE, BRL to BVSP, MXN to MXX and TWD to TWII, all with the `.INDX` suffix. GBP and other currencies have no tracked local currency index. Bond, commodity, multi-asset and other funds have no suitable benchmark among these equity indices. Without a suitable benchmark or stored index bars, the fund return is saved with null benchmark and excess returns. These indices are market proxies, not each fund's tracked index, and price returns exclude distributions.

The operator needs to ship an image with this job, populate the ETF and index `asset_bars` series through the existing EODHD jobs, and check that an eligible BUY_ZONE pick has an entry price, entry date and at least 30 days of closes. The outcomes CronJob is already scheduled daily at 06:50 Europe/Bratislava. This change needs no schema migration; the non-US outcomes path reads stored bars without a vendor call. Derived EODHD outcomes stay in the owner-authenticated ETF view.

The stock judge keeps its Claude CLI subscription provider and receives stored EODHD revenue, EPS, insider and catalyst facts when `EODHD_PRIVATE_USE=on`, plus fixed rule and chart results. The model has no web tools. Its input builder excludes earlier web research findings and consensus prose. It retains stored SEC citation links without document text or quotes. Each fact carries its source, date first observed, and stored provenance key. The runner keeps the figure check and English/Slovak parity check.

Both model runners log expected tokens before a call and actual input, output and cache tokens after it. `AI_JUDGE_MONTHLY_TOKEN_CAP` defaults to 2,000,000 tokens across all recorded AI calls in the UTC month; `AI_EXPECTED_OUTPUT_TOKENS` defaults to 30,000 per call. The estimate is prompt characters divided by three, rounded up, plus that output allowance. A missing usage report stops the call. The existing AI budget ledger records completed judge and ETF calls. For a local offline check, pass `--dry-run --input-file <json>` to either runner. Dry run reports the expected tokens and makes no model call or ingest write.

EODHD-derived ETF figures stay behind the gates above, and ETF picks stay owner only. Keep `EODHD_PRIVATE_USE=on` only in that private environment, and leave the public display path disabled until licensing is settled. The judge CronJob stays suspended until its private web path and credentials are checked on the cluster.
