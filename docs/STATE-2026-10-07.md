Saturday only: collect-alphavantage 08:00, discovery 09:30.

Still suspended on purpose: backup, retention, scan-claude, scan-codex.

The AI jobs run at night so the daytime 5-hour window of the subscription stays free. Each job reads the subscription usage (five-hour and weekly percent) before and after it runs and logs `USAGE ...`. A real cutoff by Anthropic logs `ANTHROPIC CUTOFF` and leaves the remaining tickers for the next run. There is no monthly budget. Report: `npm run ai-usage` (needs `DATABASE_URL`).

## Things to look at in a few days

1. Did each night finish? `kubectl -n invest get jobs` and `/api/health` (`lastScoreDate` should be the latest US session).
2. Gate: how many tickers per night did detect mark as changed, and did extract run only for them? If it runs for 20 or more tickers on a day with no new filings, the gate or the input hash is too loose. This is the main cost question.
3. Usage: run `npm run ai-usage`. Peak five-hour window, weekly percent, number of cutoffs. If the usage endpoint answers 401 or 403 for the scanner token, the log says `USAGE unavailable` and the report falls back to token counts.
4. Ten tickers have fundamentals 0 or technical 0 with total 2 to 8 (REGN, ROKU, SE, UBER, ENPH, META fundamentals, SMCI, PANW, SHOP, ZS). This looks like missing data, not a real zero. Check whether the extractor or reconcile found nothing, or whether the rule truly fails. Not diagnosed yet.
5. Held tickers with a low state: AMZN and GOOGL show Ignore. The dashboard labels held tickers with "V portfóliu"; confirm that label shows on the live page.
6. Discovery: first run is Saturday 2026-10-10 09:30. `discovery_candidates` is empty now. Check that it produced at most the configured number of candidates and that none got through unreviewed.
7. Track record: `record_snapshots` should gain one dated snapshot per night. Signals stay pending until 30 days have passed.
8. Portfolio page: chart from zero with the headline return. Check it against the IBKR statement once.
